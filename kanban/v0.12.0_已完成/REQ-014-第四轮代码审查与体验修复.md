# REQ-014 第四轮代码审查与体验修复

## 背景

v0.11.0 完成后，继续按「检查明显 Bug、有问题的逻辑和体验缺陷」做第四轮复查。本轮从输入健壮性、系统维护、盘点数据安全和报表口径四个方向检查，确认并修复了以下问题：

1. **非法数值可以绕过校验**：金额/单价/数量的 JSON 反序列化允许字符串 `"NaN"`、`"Inf"`；这些值能通过 `< 0` 等比较，最终以 500 和数据库约束错误结束，而不是明确的 400 参数错误。
2. **不存在的角色可以创建用户**：`CreateUser` / `UpdateUser` 不校验 `role_id` 是否存在。接口可以创建 `role_id=9999` 的账号，该账号能登录但没有任何权限，且角色列显示为空，属于不可恢复的脏数据。
3. **同一秒连续备份失败**：备份文件名只精确到秒。第一次备份成功后，同一秒内再次备份会命中 `VACUUM INTO` 的目标文件已存在错误，返回 500；并发备份/恢复也没有互斥保护。
4. **非法日期可以写入单据**：`model.NormDate` 对无法解析的输入会原样截取前 10 位，`2026-13-99` 这类日期能保存成功，影响列表排序与报表筛选。
5. **盘点切换仓库时存在旧数据串仓风险**：切换仓库后旧请求仍可能返回并覆盖新仓库明细；请求失败时旧仓库明细也不会清空。此时点击保存，会把旧仓库的商品和实盘数量写入新仓库的盘点单。另外，同一仓库点击「刷新账面库存」会丢掉手工添加的零库存/盘盈商品。
6. **报表按快照名称分组**：商品、客户、供应商重命名后，销售/采购/客户/供应商排行会把同一主数据拆成多行；销售/采购排行金额使用明细金额，不包含单据级优惠和其他费用，与首页看板、客户/供应商排行口径不一致。
7. **库存查询统计文案与实际筛选不一致**：选择某个仓库后，顶部统计仍显示「全部仓库合计」。
8. **README 与实际报表页面不一致**：README 列出「商品毛利」报表，但页面没有该页签；销售排行已经包含成本、毛利与毛利率列。

## 用户故事

- 作为接口调用者或导入工具，我希望非法数值/日期被明确拒绝，而不是得到 500 或写入脏数据。
- 作为系统管理员，我希望创建/修改用户时只能选择真实存在的角色，不存在的角色直接被拒绝。
- 作为维护人员，我希望连续备份不会因为文件名冲突失败，每次备份都有独立文件；备份和恢复不会互相踩踏。
- 作为盘点人员，我希望切换仓库或刷新账面库存时，页面上的明细始终对应当前仓库，旧请求和失败请求不能污染表单；刷新不应丢掉我已录入的盘盈商品。
- 作为报表使用者，我希望基础资料改名后排行仍是一行，销售/采购排行金额与首页、客户/供应商排行使用同一结算口径。
- 作为查看库存的人员，我希望统计文案与实际筛选条件一致。
- 作为新用户，我希望 README 中列出的报表都能在页面上找到对应入口。

## 验收标准

### P1（数据正确性 / 输入安全）

- [x] `Money`、`Price`、`Qty` 的 JSON 反序列化拒绝 `NaN`、`+Inf`、`-Inf`；数据库扫描也不接受非有限数值。
- [x] 通过 API 提交 `qty` / `price` / `amount` 为 `"NaN"` 或 `"Inf"` 时返回 400，不写入任何单据，不返回 500。
- [x] `CreateUser` / `UpdateUser` 在 `role_id>0` 但角色不存在时返回 `ErrBadRequest`，用户表和角色归属不改变；`role_id=0` 的「未分配角色」语义保持不变。
- [x] 单据日期（采购、销售、收付款、盘点、调拨）在保存时校验，`2026-13-99`、`2026-02-30` 等非法日期返回 400 且不落库；空日期仍按今天处理，带合法日期前缀的输入按前 10 位规范化。
- [x] 同一秒内连续两次备份返回不同的文件名，两次都成功；备份列表包含两个文件。
- [x] 备份与恢复使用同一互斥锁，避免并发 `VACUUM INTO` / 恢复互相干扰。
- [x] 盘点切换仓库时立即清空旧仓库明细；较早发出的库存请求后返回时不能覆盖当前仓库结果。
- [x] 盘点库存请求失败时清空明细并给出错误提示，不允许把旧仓库明细保存到新仓库。
- [x] 盘点刷新同一仓库时保留已录入的实盘数量、备注，以及已手工添加但账面为 0 的商品行。
- [x] 盘点明细加载中不能保存，避免把空/旧明细提交。

### P2（报表口径 / 体验）

- [x] 销售排行金额按单据结算金额分摊到明细（优惠冲减、其他费用计入），各商品金额合计与首页销售/客户排行一致；采购排行同理。
- [x] 销售排行成本与毛利仍精确到分，原有精度测试不放宽。
- [x] 商品/客户/供应商改名后，销售排行、采购排行、客户排行、供应商排行按主数据 ID 聚合为一行，并展示当前名称（缺失时回退快照名称）。
- [x] 库存查询在筛选仓库后，统计卡片文案显示当前筛选仓库，不再写「全部仓库合计」。
- [x] README 的报表清单与实际页面一致，并注排行采用结算口径。
- [x] 新增 store/API/组件测试覆盖上述行为；原有测试不放宽、不删除。
- [x] `make test-all`、`make vet`、`make web`、`go build ./...` 通过；`make test-e2e` 通过。

## 实现方案

- **影响范围**：
  - 后端：`internal/model/types.go`、`internal/store/user.go`、`internal/store/report.go`、`internal/store/doc.go`、`internal/store/payment.go`、`internal/store/stock.go`、`internal/api/api.go`、`internal/api/handlers_system.go`。
  - 前端：`web/src/pages/stock-takes.jsx`、`web/src/pages/stocks.jsx`。
  - 测试：`internal/model/types_test.go`、`internal/store/req014_test.go`、`internal/api/req014_test.go`、`web/test/components/stock-takes.test.jsx`、`web/test/components/stocks.test.jsx`。
  - 文档/版本：`README.md`、`main.go`、`Makefile`、`web/package.json`、`web/package-lock.json`、`web/dist`、本需求文档。
- **数据模型 / 数据库变更**：无表结构变更，无需重建开发库。
- **API 变更**：不新增接口；非法数值、非法日期、非法角色返回 400；备份文件名增加碰撞规避。
- **报表实现**：
  - 排行查询按 `product_id` / `partner_id` 聚合，使用 `LEFT JOIN` 当前主数据名称并回退快照。
  - 销售/采购排行金额按单据明细金额比例分摊 `settle_amount`；明细金额为 0 时按数量分摊，确保单据级优惠/费用落到商品行。
- **盘点实现**：
  - `loadBook` 增加请求序号，忽略过期响应；切换仓库先清空明细。
  - 切换仓库失败时清空明细并提示；刷新同一仓库失败时保留当前明细。
  - 同一仓库刷新时以当前明细为基础合并账面库存，保留手工行和已填实盘数。
  - `bookLoading` 时禁用保存并增加保存前守卫。
- **测试计划**：
  1. 先补能复现问题的失败测试：NaN 500、非法角色创建成功、同一秒备份冲突、排行改名拆行、优惠后排行金额不符、非法日期落库。
  2. 再实现修复并确认测试通过。
  3. 盘点组件测试覆盖乱序响应、失败清空、刷新保留手工行、加载中禁用保存。
  4. 完成后执行 `make test-all`、`make vet`、`make web`、`go build ./...`、`make test-e2e`。
