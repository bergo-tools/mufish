# REQ-011 金额计算精度修复

## 背景

继续复查金额与库存计算时发现：`model.AmountOf` 使用 `float64` 做“数量 × 单价”后再四舍五入到分，遇到刚好半分的组合会因二进制浮点表示误差向错误方向舍入。

可复现例子：

- 数量 `0.7`，单价 `0.05` 元。数学金额为 `0.035` 元，应四舍五入为 `4` 分；
- 当前实现计算 `0.7 * 0.05 * 100` 得到约 `3.4999999999999996`，`math.Round` 后变成 `3` 分，少计 1 分。

该函数用于采购/销售明细金额、单据合计、盘点差异金额、调拨金额等。少计 1 分会造成明细与合计、库存成本与结算金额不一致，属于金额领域的明显缺陷。

## 用户故事

作为录入采购/销售单的用户，我希望“数量 × 单价”的金额严格按分四舍五入，不因浮点误差少计或多计 1 分。

## 验收标准

- [x] `AmountOf(QtyFrom(0.7), PriceFrom(0.05))` 返回 `Money(4)`（0.04 元）。
- [x] 负数数量按绝对值半分仍然“远离零”舍入：`-0.7 × 0.05` 返回 `Money(-4)`。
- [x] 原有正常金额、零数量、零单价用例保持通过。
- [x] 新增测试覆盖半分边界和负数量，修复前测试必须失败。
- [x] `make test-all`、`make vet`、`make web`、`go build ./...` 通过；本次不改前端，`make test-e2e` 作为回归。
- [x] 版本号更新为 0.9.0，`web/dist` 重新构建并提交。

## 实现方案

- 影响范围：`internal/model/types.go` 的 `AmountOf`，以及金额/库存计算调用方。
- 数据模型 / 数据库变更：无。
- 公式：数量统一为 4 位小数（`q4 = qty × 10000` 的四舍五入整数），单价为万分之一元（`p4`），
  金额（分）= `round(q4 × p4 / 1,000,000)`。
- 使用整数/大整数运算避免浮点误差和乘法溢出，舍入规则保持“四舍五入、远离零”。
- 测试计划：在 `internal/model/types_test.go` 增加半分边界、负数量和常规金额断言；全量回归。
