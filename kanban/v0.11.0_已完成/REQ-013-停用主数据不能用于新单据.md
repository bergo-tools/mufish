# REQ-013 停用的往来单位与资金账户不能用于新单据

## 背景

仓库已经对停用仓库做了后端校验，但停用的往来单位、资金账户仍可通过接口用于新建采购、销售、收付款单：前端下拉只加载启用记录，用户从旧页面直接提交、使用接口或历史草稿时仍可能写入停用对象，造成“下拉里找不到，但单据能保存”的不一致。

同时需要保留历史单据的可处理性：草稿创建后如果对应单位或账户被停用，仍应允许确认，而不是把已存在的草稿锁死。

## 用户故事

作为录入采购、销售、收付款单的用户，我希望停用的供应商、客户、资金账户不能被选入新单据，避免把业务记到已停用的对象上；作为财务人员，我希望停用前已经保存的草稿仍能正常确认。

## 验收标准

- [x] 停用供应商不能用于新建采购单，返回 400 且不写入采购单。
- [x] 停用客户不能用于新建销售单，返回 400 且不写入销售单。
- [x] 停用往来单位不能用于新建收付款单，返回 400 且不写入收付款单。
- [x] 停用资金账户不能用于新建非往来冲抵收付款单，返回 400 且不写入收付款单。
- [x] 往来冲抵（不需要资金账户）不受资金账户停用影响。
- [x] 创建时单位、账户均启用的草稿，在二者被停用后仍可确认；确认后账户余额正确变化。
- [x] 既有正常流程测试不回退，补充 store 与 HTTP 回归测试。
- [x] `make test-all`、`make vet`、`make web`、`go build ./...` 通过。

## 实现方案

- **影响范围**：`internal/store/doc.go`、`internal/store/payment.go`、`internal/store/req013_test.go`、`internal/api/req013_test.go`、`README.md`、版本号文件。
- **数据模型 / 数据库变更**：无。
- **API 变更**：无新增接口；保存采购/销售/收付款单时对停用对象返回 400。
- **后端**：
  - `loadPartnerForRole` 校验往来单位状态，新建/修改单据保存时使用；新增 `loadPartnerForRoleAllowDisabled` 供收付款确认使用，避免锁死历史草稿。
  - `SavePayment` 读取资金账户时同时校验 `status=1`；往来冲抵仍允许 `account_id=0`。
  - `ConfirmPayment` 使用允许停用的往来单位读取函数。
- **测试计划**：
  1. 先写失败测试：停用供应商仍能新建采购单、停用客户仍能新建销售单、停用账户仍能新建收款单。
  2. 修复后补“停用后历史草稿仍可确认”和“往来冲抵不选账户”边界测试。
  3. 补 HTTP 层 400 与“失败不写入”断言，执行全量回归与构建。

- 状态：已完成
- 变更文件：
  - 后端：`internal/store/doc.go`、`internal/store/payment.go`、`internal/store/req013_test.go`、`internal/api/req013_test.go`。
