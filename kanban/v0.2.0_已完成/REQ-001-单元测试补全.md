# REQ-001 单元测试补全

## 背景

项目最初只有 `internal/store` 与 `internal/api` 的少量集成测试，基础资料、报表、会话、密码、金额类型、CSV、设置等模块缺少直接覆盖。核心业务（库存成本、单据状态、收付款）虽有测试，但边界、非法输入和回滚场景不足，后续改动容易产生回归。

## 用户故事

作为项目维护者，我希望项目拥有覆盖主要业务分支的自动化测试，以便在重构和新增功能时快速发现回归，而不是依赖手工点击验证。

## 验收标准

- [x] 为 `internal/model` 增加金额/单价/数量、权限集合、日期规范化的单元测试。
- [x] 为 `internal/auth` 增加口令散列、校验、会话令牌生成的单元测试。
- [x] 扩展 `internal/store` 测试，覆盖商品/分类/往来单位/仓库/账户 CRUD、自动编码、删除引用保护、库存查询、报表、收付款校验、会话等。
- [x] 扩展 `internal/api` 测试，覆盖登录/注销/改密/权限、基础资料 CRUD、设置、导出、错误码与分页。
- [x] 为 `web/src/format.js` 增加纯函数单元测试（Node 内置 test runner）。
- [x] `go test ./...` 全绿，且新增测试在修复前能暴露对应缺陷。
- [x] 不删除、不弱化任何已有测试。

## 实现方案

- 影响范围：测试文件、Makefile / package.json 的测试命令。
- 数据模型 / 数据库变更：无。
- API 变更：无。
- 前端变更：仅新增测试，不改变运行时代码。
- 测试计划：按包分层补充，优先覆盖核心业务与本次代码审查发现的缺陷。

## 实现情况

- 状态：已完成

- 变更文件：
  - `internal/model/types_test.go`：Money / Price / Qty、JSON、扫描、AmountOf、NormDate、状态文案。
  - `internal/model/perm_test.go`：46 个权限点、权限集合、超级权限通配。
  - `internal/auth/password_test.go`：PBKDF2 散列与校验、非法散列、令牌、随机口令。
  - `internal/store/regression_test.go`、`regression2_test.go`：自动编码阻塞、空编码更新、分类环、应收应付口径、进销存区间、销售排行精度、收付款关联校验、盘点陈旧账面、调拨金额、恢复回滚、零库存预警。
  - `internal/store/catalog_extended_test.go`、`category_filter_test.go`、`stock_report_test.go`、`store_queries_test.go`：基础资料 CRUD、分类树、权限/用户/会话/日志、库存查询、报表、收付款查询与删除。
  - `internal/api/handlers_basic_test.go`、`handlers_extended_test.go`、`handlers_lifecycle_test.go`：认证生命周期、CRUD 与错误码、权限、设置、收付款、盘点/调拨、用户/角色/日志、CSV 导出、备份恢复。
  - `web/test/format.test.js`：格式化、状态文案、单位换算等纯函数。
  - `Makefile`、`web/package.json`：新增 `test-web`、`test-all`、`cover` 与 `npm test`。
  - `README.md`、`AGENTS.md`：补充测试命令与开发约定。

- 测试与验证结果：
  - `make test-all`：Go 全部包 + 前端 7 个测试通过。
  - `go test -count=1 ./...`：通过。
  - `go test -race -count=1 ./...`：通过，未发现数据竞争。
  - 覆盖率：`store` 75.9%、`api` 73.6%、`auth` 84.6%、`model` 87.5%（`go test -cover ./...`）。

- 遗留问题 / 后续事项：
  - 前端目前只覆盖纯函数，尚未引入组件测试或 E2E（Playwright 等）。
  - 报表、导出等场景可以做基于真实数据的基准测试，以观察大数据量下的性能。
