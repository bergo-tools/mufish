# REQ-007 第二轮代码审查与体验修复

## 背景

v0.4.0 已完成第一轮审查（REQ-006）并归档。本轮继续从后端账务/权限、前端数据加载与报表交互三个方向做第二轮审查，重点检查上一轮未覆盖的“数据正确性”和“失败路径”。

本轮已确认以下问题，其中 3 个属于会算错账、削弱权限或覆盖真实配置的 P0 问题：

1. **作废冲销使用当前移动平均成本，而不是原流水的金额**。采购入库后如果又发生其他入库，再作废原采购单，剩余库存金额会被按当前平均价冲减，导致结存成本失真；调拨、销售、盘点作废同理。
2. **管理员在“编辑用户”里修改口令后，旧会话仍有效**。只有“重置口令”和用户自己改口令会删除会话，编辑用户口令不会。
3. **系统参数页加载失败时返回空对象，页面用默认值填充并允许保存**。用户一旦保存，会把真实系统参数覆盖成默认值。
4. **销售单优惠金额可以超过明细金额**。后端把结算金额截断为 0，前端也显示负数结算，优惠差额被静默吞掉；采购单已有校验，销售单没有。
5. **分页列表存在并发响应覆盖**。快速切换筛选/翻页时，较早的请求可能后返回并覆盖新结果。
6. **删除当前页最后一条后页码越界**，页面停留在空页。
7. **“往来冲抵”仍强制选择资金账户**，但冲抵不产生现金流动，账户字段没有业务意义。
8. **资金流水页显示搜索框，但关键字没有传给后端**，输入后无任何效果。
9. **客户/供应商排行隐藏了日期筛选，但后端仍按默认月份过滤**，界面与数据口径不一致。

## 用户故事

- 作为财务/老板，我希望作废单据后剩余库存成本仍然准确，不能因为冲销顺序或后续入库而算错账。
- 作为系统管理员，我希望修改或重置他人口令后，旧会话立即失效。
- 作为系统管理员，我希望系统参数加载失败时明确报错，绝不能把默认值保存回去覆盖真实配置。
- 作为销售/开单人，我希望优惠金额不能超过明细金额，错误要明确提示。
- 作为日常操作人员，我希望快速筛选、翻页、删除后不会看到旧数据或空白页。
- 作为财务，我希望往来冲抵不需要选择资金账户，资金流水搜索能真正生效。
- 作为报表使用者，我希望界面显示的筛选条件与实际统计口径一致。

## 实现方案

- **影响范围**：`internal/store/doc.go`、`user.go`、`payment.go`、`report.go`；`internal/api/handlers_finance.go`、`handlers_basic.go`（必要时）；`web/src/ui.jsx`、`pages/sales.jsx`、`payments.jsx`、`reports.jsx`、`settings.jsx`；对应测试与 `web/dist`。
- **数据模型 / 数据库变更**：不需要改表；冲销只改运行时计算逻辑。
- **API 变更**：
  - 销售优惠超限返回 400；
  - `offset` 允许 `account_id=0`；
  - 资金流水新增 `keyword` 查询参数；
  - 用户修改口令删除会话。
- **前端变更**：
  - 销售保存校验优惠上限；
  - 分页 hook 增加请求序号与页码收敛；
  - 冲抵时隐藏/取消资金账户必填；
  - 资金流水传 keyword；
  - 设置页加载失败禁用保存；
  - 客户/供应商排行显示日期筛选。
- **测试计划**：
  1. 库存冲销成本：先复现“作废后剩余结存金额错误”，再修复；
  2. 会话失效：创建会话→修改口令→断言旧 token 无效；
  3. 设置页：mock 接口失败，断言错误态且保存不可用；
  4. 销售优惠：金额边界、失败不改变数据；
  5. 分页：乱序响应、页码越界；
  6. 冲抵：无账户可保存/确认，非冲抵仍拒绝无账户；
  7. 资金流水关键字过滤；
  8. 完成后执行 `make test-all`、`make vet`、`make web`，涉及核心流程时跑 `make test-e2e`。
