# REQ-009 单据详情、库存提示与独立调账

## 背景

v0.6.0 已归档，第三轮审查记录在案的 5 个体验问题需要继续处理。用户在 v0.6.0 回顾中确认开始修复，并要求资金账户余额调整必须生成独立调账记录，而不是直接覆盖余额。

本轮要解决的问题：

1. 单据列表有确认/作废操作，但详情弹窗没有；从首页“最近单据 → 查看”进入详情后无法直接确认或作废。
2. 长表单点击遮罩或按 Esc 会直接关闭并丢弃未保存内容，没有防误触。
3. 销售开单看不到当前仓库可用库存，只能等确认时才发现库存不足。
4. 搜索框的“清空”按钮只清输入值，部分页面不会刷新列表，必须再按查询/回车。
5. 编辑资金账户时直接改余额会覆盖账户余额，不生成业务记录；需要改为独立的“余额调账”动作，并保留完整的调账记录（调整前、调整后、金额、原因、操作人、时间）。

## 用户故事

- 作为开单/仓管人员，我希望在单据详情里直接确认或作废，不用退回列表再找一遍。
- 作为录入人员，我希望误点遮罩或按 Esc 时不要丢掉刚填的长表单。
- 作为销售，我希望选商品时看到当前仓库的可用库存，数量超过库存时立即得到提示。
- 作为日常操作人员，我希望点搜索框的清空按钮后列表立即恢复为无关键字结果。
- 作为财务/管理员，我希望账户余额调整是一条独立记录，能追溯调整前后金额、原因和操作人；账户编辑不能悄悄改余额。

## 验收标准

### P1（功能）

- [x] P1-1：采购、销售、盘点、调拨详情弹窗按权限和状态提供“确认/完成”“作废”操作；操作成功后列表和详情同步刷新；从首页最近单据打开详情也能操作。
- [x] P1-2：资金账户新增“余额调账”接口与前端入口；调账必须填写原因，生成独立记录（账户、调整前、调整后、差额、原因、操作人、时间）；调账前后余额变化正确。
- [x] P1-3：账户编辑接口不再修改余额；前端编辑账户时余额只读并提示通过“调账”修改；失败路径不改变余额，也不留下调账记录。
- [x] P1-4：每个账户可查看调账记录列表；存在调账记录的账户不能直接删除（避免历史记录失去归属），可改为停用。

### P2（体验）

- [x] P2-1：长表单弹窗默认不响应遮罩点击/Esc 关闭；保留显式“取消/关闭”。

- [x] P2-3：搜索框“清空”后立即按空关键字刷新列表（采购、销售、用户、日志、收付款、报表、盘点、调拨、库存流水、库存查询）。
- [x] P2-4：新增/修改账户、调账、查看调账记录的权限与错误提示正确。

## 实现方案

- **数据库**：新增 `account_adjustments` 表，记录账户 ID/名称、调整前后余额、差额、原因、操作人、时间；增加账户和历史时间索引。
- **后端**：
  - 新增 `AdjustAccount`、`ListAccountAdjustments`；
  - `SaveAccount` 更新分支忽略余额字段；
  - `DeleteAccount` 检查调账记录；
  - 新增 `POST /accounts/{id}/adjust`、`GET /accounts/{id}/adjustments`；
  - 调账写入操作日志（旧值、新值、原因）。
- **前端**：
  - 账户页新增“调账/记录”入口与记录弹窗；编辑账户余额只读；
  - 采购、销售、盘点、调拨详情增加确认/作废；
  - Modal 增加 `closeOnMask` / `closeOnEsc`，长表单禁用误触关闭；
  - 销售表单按仓库获取可用库存并提示；
  - SearchBox 增加 `onClear`，各列表清空即刷新。
- **测试计划**：先补 store/API/组件失败测试，再实现；覆盖金额、权限、失败回滚、记录不可丢失、库存提示和清空查询。
