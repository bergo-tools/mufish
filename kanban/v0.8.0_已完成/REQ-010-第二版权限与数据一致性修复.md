# REQ-010 第二版权限与数据一致性修复

## 背景

v0.7.0 完成后继续按“检查明显 Bug、问题逻辑和体验缺陷”的目标复查，发现以下问题：

1. 内置「财务」角色只有 `product:view`、`stock:view`、`report:view`，没有 `category:view`；但商品、库存、报表页面都会调用 `GET /categories/flat` 加载分类下拉，导致该角色打开这些页面时接口返回 403，分类筛选为空，报表页还会因为 `Promise.all` 整体失败而静默丢掉全部筛选下拉。
2. 收付款单只校验往来单位存在，没有校验单位类型。可以给供应商开“收款单”、给客户开“付款单”，造成应收应付余额方向错误；确认旧草稿时也没有二次校验。
3. 编辑往来单位时可以把已有销售单的客户改成“纯供应商”，或把已有采购单的供应商改成“纯客户”，应收应付报表按单位类型过滤后会直接隐藏这些欠款。
4. 删除仓库只检查库存、采购、销售、库存流水和调拨，没有检查盘点单；删除后盘点单仍可完成，并把库存写到已不存在的仓库。
5. 保存商品时不校验分类是否存在，接口可以写入不存在的 `category_id`，页面会显示为空分类。
6. 看板“最近单据”表格传入函数形式的 `rowKey`，但 `Table` 只支持字符串键，实际退化为数组下标；同一位置的销售/采购行可能复用错误组件状态。
7. 角色权限页在只读状态下，“超级管理员”开关仍可点击，但点击后不会保存，表现为“可以操作但没有效果”。

## 用户故事

作为使用内置角色或自定义角色的用户，我希望页面需要的下拉数据与页面查看权限一致，不要因为缺少一个独立权限而出现 403 或空白筛选。

作为财务人员，我希望收付款单只能选择类型匹配的往来单位，并且历史单据在确认时也会再次校验，避免应收应付被记到错误方向。

作为管理员，我希望在修改基础资料或删除仓库时，系统阻止会产生孤儿数据或隐藏欠款的操作，而不是事后才发现报表对不上。

## 验收标准

- [x] `GET /api/v1/categories/flat` 对 `category:view`、`product:view`、`stock:view`、`report:view` 任一权限开放；只有 `dashboard:view` 的用户仍返回 403。
- [x] 新增/修改商品时，`category_id>0` 必须指向已存在的分类，否则返回 400，且商品不被写入。
- [x] 收款单只能选择客户或“客户兼供应商”，付款单只能选择供应商或“客户兼供应商”；保存和确认两个阶段都校验，失败时付款单、关联单据金额、账户余额均不变。
- [x] 往来单位类型修改时，如果新类型会排除已有销售单（改为纯供应商）或已有采购单（改为纯客户），返回 400 并保持原数据；改为 `both` 不受影响。
- [x] 仓库存在任何盘点单（含草稿、已完成）时不能删除，返回 409。
- [x] `Table` 的 `rowKey` 支持函数；看板最近单据使用 `doc_type-id` 作为键。
- [x] `Switch` 支持 `disabled`；角色权限页只读时“超级管理员”开关不可操作。
- [x] 报表页下拉数据加载失败时显示错误和“重试”，不再静默显示空筛选。
- [x] 新增回归测试覆盖上述后端与前端行为；原有测试不放宽、不删除。
- [x] `make test-all`、`make vet`、`make web`、`go build ./...`、`make test-e2e` 通过。
- [x] 版本号更新为 0.8.0，`web/dist` 重新构建并提交。

## 实现方案

- 影响范围：API 路由权限、商品/往来单位/收付款/仓库 store、报表页、表格与开关组件、角色权限页。
- 数据模型 / 数据库变更：无表结构变更。
- API 变更：
  - `GET /categories/flat` 权限扩为 `category:view|product:view|stock:view|report:view`；
  - 无新增接口。
- 前端变更：
  - `Table` 支持函数 `rowKey`；
  - `Switch` 支持 `disabled`，角色权限页只读时禁用；
  - 报表页展示下拉加载失败与重试。
- 测试计划：
  - API：分类权限矩阵、商品分类校验、收付款单位类型、往来单位类型变更、仓库删除；
  - store：仓库盘点引用、收付款确认回滚；
  - 前端：Table 函数 rowKey、Switch disabled、报表下拉错误提示；
  - 全量回归与 E2E。
