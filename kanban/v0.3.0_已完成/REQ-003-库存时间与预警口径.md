# REQ-003 库存流水时间口径与预警口径统一

## 背景

当前库存流水只有 `created_at`（确认/记账时间），而单据允许填写业务日期。报表、库存流水的日期筛选都按 `created_at`，导致补录历史单据后，按业务日期查询不到或归错期间。

另外，库存预警存在两套口径：
- 看板与 `LowStockList` 会把从未入库、没有 `stocks` 记录的商品算作低库存；
- `ListStocks(low=true)` 只查询 `stocks` 表，永远看不到零库存商品。

需要统一为可解释的业务口径。

## 用户故事

作为仓库/财务人员，我希望按业务日期查询库存流水和进销存报表，并且库存预警能稳定包含零库存商品，以便补录历史单据和对账时数据落在正确的期间。

## 验收标准

- [x] `stock_moves` 增加业务日期字段 `biz_date`。项目未上线，**不做旧库兼容迁移**，开发/测试库直接重建。
- [x] 采购、销售、盘点、调拨、期初、作废冲销写入正确的 `biz_date`。
- [x] 库存流水列表、导出的日期筛选按 `biz_date`，同时保留记账时间展示。
- [x] 进销存汇总的期初/本期/期末按 `biz_date` 计算。
- [x] `ListStocks(low=true)` 与 `LowStockList` 对零库存商品的口径一致。
- [x] 增加回归测试：历史日期单据能在对应期间查询到，且不会出现在错误期间。

## 实现方案

- 数据模型：`model.StockMove` 增加 `BizDate`。
- 数据库：`schema.sql` 增加 `biz_date` 字段与索引；不写迁移/回填逻辑，旧开发库删除后重新初始化。
- 业务写入：`stockMoveReq` 增加 `BizDate`，采购/销售/盘点/调拨传入单据日期；作废冲销沿用原流水业务日期；期初库存使用初始化日期。
- 查询：`ListStockMoves`、`InoutSummary` 日期条件改为 `biz_date`。
- 预警：抽取共享的 `lowStockPage`，`ListStocks(OnlyLow)` 与 `LowStockList` 共用；未指定仓库时按全部仓库汇总，指定仓库时按该仓结存。
- 前端：库存流水表增加业务日期/记账时间两列；导出增加业务日期列。
