# REQ-012 期初余额类型校验与单据金额合计一致性

## 背景

继续复查往来单位与单据金额展示时发现两个会造成用户看到的数据不一致的问题：

1. 应收应付报表按往来单位类型筛选，但首页应收/应付合计和往来单位列表没有按类型区分期初余额。新建“纯供应商”时可以填写期初应收（或新建“纯客户”时可以填写期初应付），保存成功后首页/列表会计入这笔金额，应收应付报表却完全看不到，形成“总额对不上、明细找不到”的数据不一致。
2. 后端 v0.9.0 已把每条明细的“数量 × 单价”按分四舍五入后求和；采购、销售、盘点、调拨页面仍用浮点数先乘再一次性格式化。多条半分边界明细时，页面“合计金额”可能与每行金额之和、保存后的服务端合计相差 1 分。例如两行 `0.7 × 0.05`：每行应显示 0.04，页面合计却显示 0.07，服务端保存为 0.08。

## 用户故事

- 作为财务人员，我希望纯供应商不能填写期初应收、纯客户不能填写期初应付，首页应收应付与应收应付报表始终能对上。
- 作为录入采购/销售/盘点/调拨单的用户，我希望页面显示的每行金额、合计金额与保存后服务端计算的结果完全一致，不因浮点误差差 1 分。

## 验收标准

### P1（数据一致性）

- [x] 新建纯供应商时期初应收必须为 0，新建纯客户时期初应付必须为 0；违反时返回 400，且不写入往来单位。
- [x] 修改往来单位同样校验；已有客户的期初应收、已有供应商的期初应付不受影响。
- [x] 首页应收/应付合计、往来单位列表的应收/应付列按单位类型统计期初余额：客户/客户兼供应商才计期初应收，供应商/客户兼供应商才计期初应付。
- [x] 已有历史数据即使类型与期初余额不匹配，首页与应收应付报表也不再出现总额比明细多的情况。

### P1（金额展示）

- [x] 新增前端精确金额助手，按后端 `AmountOf` 相同规则（数量 4 位、单价 4 位，金额按分四舍五入、负数远离零）计算单行金额。
- [x] 采购、销售单据的每行金额、合计金额、结算金额、优惠上限校验均按“逐行分金额求和”计算。
- [x] 盘点差异金额合计、调拨金额合计使用同一精确规则。
- [x] 两行 `0.7 × 0.05` 的采购单页面合计显示 0.08，不再显示 0.07；负数量盘点差异保持对称。

### 其他

- [x] 补后端 store 回归测试、前端纯函数与组件回归测试；不删除或弱化既有测试。
- [x] `make test-all`、`make vet`、`make web`、`go build ./...` 通过；前端核心表单改动执行 `make test-e2e`。
- [x] 版本号更新为 0.10.0，`web/dist` 重新构建并提交。
