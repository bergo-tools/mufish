# REQ-008 第三轮代码审查与体验修复

## 背景

v0.5.0 已完成第二轮审查并归档。本轮继续从权限、库存成本、报表口径、基础资料完整性和前端交互五个方向做第三轮审查，重点检查前两轮未覆盖的边界路径和“上次没修完的体验问题”。

本轮确认以下问题，其中 8 个属于会造成数据错误、权限越界、报表失真或误导用户的缺陷：

1. **首页走势接口越权**：`GET /dashboard/trend` 只校验 `dashboard:view`，没有像 `GET /dashboard` 那样按销售/采购模块权限屏蔽数据。只有看板权限的账号可以直接拿到销售、采购和毛利。
2. **商品详情库存合计永远为 0**：`GetProduct` 没有查询 `stocks` 汇总，但前端详情用 `product.stock_qty` 展示，导致“库存合计”与下方分仓库存不一致。
3. **盘点差异金额少 1 分**：`SaveStockTake` 用 `int64(round4(...))` 截断小数分，遇到 4 位小数单价时差异金额与库存实际入账金额不一致。
4. **调拨确认后明细金额不更新**：确认时只更新 `transfer_items.price`，没有更新 `amount`，导致详情中“金额合计”与明细行金额对不上。
5. **商品可被草稿调拨/盘点引用后删除**：`DeleteProduct` 只检查采购、销售、库存和流水，未检查草稿调拨单/盘点单；删除后确认草稿会为不存在的商品创建库存记录。
6. **应收应付报表隐藏停用单位**：报表强制 `p.status=1`，停用但有欠款的客户/供应商会从对账表中消失，首页应收应付却仍包含这些余额，两个口径不一致。
7. **登录失败提示被覆盖**：登录接口返回 401 时，前端统一按“会话失效”处理，把“用户名或口令错误”替换成“登录状态已失效”，用户无法判断是输错还是掉线。
8. **退出后仍展示已失效的默认口令提示**：登录页的 `meta` 只在应用启动时加载；管理员改密后退出，登录页仍用旧 `meta` 显示 `admin/admin123`。

另有 6 个前端体验/可访问性问题：

9. **切换每页条数时页码不归 1**：在末页把 20 条/页切到 100 条/页，会停留在错误的页码。
10. **报表搜索每输入一个字就请求一次**：搜索框语义是回车/按钮查询，但关键字进入 `useAsync` 依赖，导致请求风暴；同时切换报表页签时旧数据可能短暂套用新表头。
11. **列表/报表失败时看起来像“暂无数据”**：多数列表页忽略 `usePagedList` 的 error，报表也没有错误态。
12. **登录页始终展示默认账号 admin/admin123**：管理员改过口令后仍展示，容易误导。
13. **导航和登录表单可访问性差**：导航项是不可聚焦的 `div`，登录输入框只有 placeholder，没有可访问名称。
14. **账户编辑提示错误**：编辑已有账户时仍提示“新建时的期初余额”，容易让用户误以为只是期初值。

此外程序版本仍显示 v0.1.0，与已完成的 v0.5.0 不一致，本次一并更新到 v0.6.0。

## 用户故事

- 作为只有看板权限的账号，我不应通过其他接口拿到无权查看的销售、采购、毛利数据。
- 作为商品管理员，我希望商品详情里的库存合计与分仓库存一致。
- 作为财务/仓管，我希望盘点差异金额、调拨明细金额与实际库存入账金额完全一致，不能出现 1 分钱误差或对不上的合计。
- 作为资料管理员，我希望被草稿单据引用的商品不能删除，避免留下孤儿库存。
- 作为财务，我希望停用单位的欠款仍出现在应收应付对账表中，不能因为停用就“消失”。
- 作为登录用户，我希望输错口令时看到“用户名或口令错误”，而不是被提示登录状态失效。
- 作为日常操作人员，我希望切换每页条数时回到第一页，报表搜索只在回车/查询时请求，切页签时不显示上一页签的旧数据；请求失败时有明确提示。
- 作为新用户，我希望登录页只在管理员仍使用默认口令时提示初始账号；改密退出后不能继续展示默认口令。
- 作为使用键盘/读屏的用户，我希望导航和登录表单可聚焦、有可访问名称。
- 作为账户管理员，我希望编辑已有账户时看到“直接修改余额不会生成收付款记录”的提示。

## 验收标准

### P1（功能缺陷）

- [x] P1-1：`GET /dashboard/trend` 与 `GET /dashboard` 使用相同的模块权限口径；无销售/采购权限时返回空走势，有销售权限但无采购权限时采购为 0；新增 API 测试。
- [x] P1-2：`GET /products/{id}` 返回正确的 `stock_qty`（各仓库结存合计）；商品详情“库存合计”与分仓明细一致；新增 store 测试。
- [x] P1-3：盘点差异金额按分四舍五入，不再截断；4 位小数单价场景下 `diff_amount` 与库存实际入账金额一致；新增 store 回归测试。
- [x] P1-4：调拨确认后 `transfer_items.amount` 同步更新为实际结转成本金额，详情明细金额合计与单据合计一致；新增 store 测试。
- [x] P1-5：商品被草稿调拨单或草稿盘点单引用时 `DeleteProduct` 返回 `ErrInUse`；删除对应草稿后可正常删除商品；新增 store 测试。
- [x] P1-6：应收应付报表包含停用但仍有余额的往来单位，且与首页应收应付口径一致；新增 store 测试。
- [x] P1-7：登录接口 401 不再触发全局会话失效，页面展示服务端返回的“用户名或口令错误”；新增前端单元测试。
- [x] P1-8：退出登录/会话失效时立即隐藏默认口令提示并重新拉取 `meta`；管理员改密退出后登录页不再展示 `admin/admin123`；新增组件测试和手工验证。

### P2（体验/可访问性）

- [x] P2-1：`usePagedList.setSize` 切换每页条数时页码归 1；新增组件测试。
- [x] P2-2：报表关键字只在回车/查询时提交，输入过程不产生请求；`useAsync` 依赖变化时清空旧数据，切换页签不显示错列内容；新增组件测试。
- [x] P2-3：`usePagedList` 请求失败时弹出错误提示；报表失败时显示错误与“重试”，不再显示“暂无数据”；新增组件测试。
- [x] P2-4：登录页仅在管理员仍使用默认口令时显示 `admin/admin123`；`GET /meta` 新增 `default_login` 字段；新增 store/API/组件测试。
- [x] P2-5：侧边栏导航使用可聚焦链接（`<a href="#/...">`）并带 `aria-current`；登录输入框有可访问名称；新增组件测试。
- [x] P2-6：账户编辑时提示“直接修改余额不会生成收付款记录”，新建时提示期初余额；构建通过并手工验证。

## 实现方案

- **影响范围**：`internal/api/handlers_basic.go`、`internal/store/catalog.go`、`stock.go`、`report.go`、`user.go`；`web/src/api.js`、`store.js`、`ui.jsx`、`app.jsx`、`styles.css`、`pages/login.jsx`、`pages/reports.jsx`、`pages/accounts.jsx`；对应测试与 `web/dist`。
- **数据模型 / 数据库变更**：无表结构变更；只补充查询、金额更新和版本信息。
- **API 变更**：
  - `/dashboard/trend` 按模块权限脱敏；
  - `/products/{id}` 返回正确的 `stock_qty`；
  - `/meta` 新增 `default_login`。
- **前端变更**：
  - 登录 401 不再全局登出，保留服务端错误文案；
  - 退出时刷新公开 `meta` 并立即隐藏默认口令提示；
  - 报表拆分“输入值/已提交值”，依赖变化时清空旧数据；
  - 分页尺寸变化重置页码；
  - 列表失败弹出错误提示，报表失败显示错误与重试；
  - 导航改用原生链接，登录输入框补 `aria-label`；
  - 账户提示按新增/编辑区分。
- **测试计划**：
  1. 先补 API/store/组件失败测试，再修复；
  2. 覆盖权限脱敏、库存金额四舍五入、调拨金额、商品删除引用、应收应付停用单位；
  3. 覆盖分页尺寸、报表请求次数、报表错误态、登录错误文案、登录提示刷新、导航链接；
  4. 完成后执行 `make test-all`、`make vet`、`make web`、`go build ./...`，并执行 `make test-e2e`。
